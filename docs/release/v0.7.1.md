# cookie-net v0.7.1 - Dependency Floor

**Date:** 2026-11-02
**Compare:** [`v0.7.0...v0.7.1`](https://github.com/jamesgober/cookie-net/compare/v0.7.0...v0.7.1)

**One advisory closed instead of argued away.** v0.7.1 requires crypt-io 1.2.2. There is no API or format change, and no code in cookie-net changed.

## What's in 0.7.1

- **crypt-io 1.2.2.** RUSTSEC-2026-0385 is an advisory against `ctutils`, whose fixed releases need Rust 1.87, so builds on Rust 1.85 and 1.86 kept the old version. cookie-net never reached the affected code, and 0.6.0 recorded that. crypt-io 1.2.2 builds HMAC and HKDF itself over `sha2`, so `ctutils` leaves the tree on every toolchain. Subkeys are byte-identical: the pinned signed and sealed format vectors pass unchanged, so existing cookies keep verifying and opening.
- **CI audits both trees.** `cargo audit` and `cargo deny` now run on the resolution Rust 1.85 gets and on the newest one. Auditing only the newest is how the gap above stayed out of sight.

## Verification

- Local gate on Windows and WSL Ubuntu, Rust stable and 1.85, every feature mode, docs for every feature set, and `cargo package` in a fresh target directory.
- No `ctutils` in the tree on either resolution; `cargo audit` and `cargo deny` clean on both.
- The fuzz targets were not rerun: no code in cookie-net changed, and the one dependency path that did change (key derivation) is pinned by the format vectors. The pre-1.0 polish milestone fuzzes every target again on the final code.
- CI green on every platform before the tag.

## What's next

`0.8.0` is the alpha, and it waits for gate-net, the sign-in gates, and web-net to be built on cookie-net. It also moves to the current parse-net, which is a breaking change because `Sink` is part of cookie-net's public API.
