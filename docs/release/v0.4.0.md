# cookie-net v0.4.0 - Signed and Encrypted

**Date:** 2026-10-23
**Compare:** [`v0.3.0...v0.4.0`](https://github.com/jamesgober/cookie-net/compare/v0.3.0...v0.4.0)

**Small client-held state that cannot be forged, read, or moved.** v0.4.0 added signed cookies (keyed BLAKE3) and encrypted cookies (XChaCha20-Poly1305), both through crypt-io, with key rings that rotate in stages across a cluster. The cookie name is inside every MAC and every AEAD, an expiry can be enforced by the server, and a value can be bound to one session.

## What's in 0.4.0

- **`Signer`** (feature `signed`). `sign("prefs", "lang=fr")` returns the value with a 30-character header; `verify(name, raw, now)` returns the value or a `Rejected` reason. `sign_until` embeds an expiry the server checks on every request; `sign_bound` ties the value to a binding (a digest of the session id) that is not stored in the cookie. The tag is 16 bytes, compared in constant time with crypt-io's `Tag::ct_eq`; verification allocates nothing and takes no lock.
- **`Sealer`** (feature `encrypted`). `seal` and `open`, with the same expiry and binding options. A random 192-bit nonce per cookie; the name, header, and binding are associated data. `open` returns a `Plaintext` that is wiped on drop; `open_into` reuses the caller's buffer and wipes it on every refusal, including an expired value.
- **Keys and rings.** `Key` (wiped on drop, redacted `Debug`), `Key::derive(master, context)` for one master serving several services, and `KeyRing` with one signing key and up to seven `Accepted` or `Retired` keys. `Signer` and `Sealer` derive their own subkeys, so one key can feed both. Fingerprints let an operator compare rings across nodes before switching keys.
- **Staged rotation.** Stage the new key everywhere with `accept`, switch with `rotated` (the old key retires at a time you choose), then drop it. A two-node simulation test shows no step refuses a cookie the other node made.
- **`Rejected`.** `Malformed`, `UnsupportedVersion`, `UnknownKey`, `BadTag`, `Expired`, each with a stable `code()` and a `severity_hint()` for the event bridge. The tag is checked before the expiry, so a forgery reports `BadTag`.
- **Formats and guide.** `docs/FORMATS.md` gives the byte-exact formats, the key derivations, and test vectors (pinned in `tests/vectors.rs`); `docs/COOKIES.md` says which cookie to use when and gives the rotation runbook.
- **`no_std`.** `signed` builds for `thumbv7em-none-eabi` with no default features (it needs an allocator at link time, because crypt-io links `alloc`).

## Verification

- Local gate on Windows and WSL Ubuntu, Rust stable and 1.85, in every feature mode, and `cargo package` in a fresh target directory.
- Every single-bit change of a signed and a sealed value refused; property tests that a value never verifies under another name, key, or binding; counting-allocator tests for signing, verifying, and opening; a constant-time smoke test.
- Fuzzing: `signed_verify` and `sealed_open`, one hour each, no findings.
- CI green on every platform before the tag.

## What's next

`0.5.0` completes the feature set: the client side (`parse_set_cookie`, the cookie-date algorithm) and a bounded cookie jar with a store trait, export and import, partitioned cookies, and fail-closed public-suffix handling, plus `Clear-Site-Data` for cookie-bomb recovery.
