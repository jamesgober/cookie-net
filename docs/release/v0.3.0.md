# cookie-net v0.3.0 - Plain Cookies

**Date:** 2026-10-23
**Compare:** [`v0.2.0...v0.3.0`](https://github.com/jamesgober/cookie-net/compare/v0.2.0...v0.3.0)

**Reading `Cookie` and writing `Set-Cookie`, with the session helpers.** v0.3.0 built the request side, the response side, and the `__Host-` session helpers against the API locked in 0.2.0. Reading is zero-copy, allocation-free, and linear; credentials are read with lookups that fail closed; and a `Set-Cookie` value that breaks any of thirteen rfc6265bis and CHIPS rules cannot be built.

## What's in 0.3.0

- **Tier 1 reading.** `get_unique(header, "__Host-sid")` returns the credential, or `Ambiguous` when the name is planted twice, when the pair limit cut the scan short, or when the header is too long. `get` and `get_all` serve preferences and repeated names; `parse` gives every pair. Inputs are any `&[u8]`-like value; names and values come back as `&str`.
- **The credential locator.** `locate` answers in one pass with the lookup, the scan's statistics, and the count of shadow names (`sid`, `__host-sid`, `SID`, `__Secure-sid` beside `__Host-sid`), plus a suggested severity for the event bridge.
- **Careful reading.** Names compared byte for byte, never trimmed, folded, or decoded; quotes kept as part of the value; `,` never a separator; `$Version` read as a name; bad pairs skipped and counted; repeated prefixed names counted in linear time. Several field lines (HTTP/2 crumbs) read as one header without copying.
- **Limits.** Header length (8,192 bytes by default), pairs (64), name length (256), value length (4,096), each checked before the work it governs; strict values by default and a lenient mode for hosts that share cookies with third-party scripts.
- **`SetCookie`.** Secure defaults (`Secure; HttpOnly; SameSite=Lax; Path=/`, host-only); a builder for `Max-Age`, `Expires`, `Domain`, `Path`, `SameSite`, `Partitioned`, extensions, and the two plainly named opt-outs `insecure` and `script_readable`; `delete` for removal cookies that match what they remove. One canonical serialization, written into any `parse_net::Sink` with the exact length known first, or into a `String`.
- **Session helpers.** `session_cookie` and `elevated_cookie` refuse a name without `__Host-` and a token under 22 bytes, and fix every attribute; `elevated_cookie` is `SameSite=Strict` with a lifetime of 60 to 3600 seconds.
- **Errors.** One `CookieError` that works with `?` everywhere, with positions instead of input bytes, a fixed message, and a stable `code()` for metrics.
- **Tests.** One test per enforced rule, citing its section; attack tests for threats T1 to T13, T19 to T23, and T28; property tests for the builder rules, crumb splitting, lookups, and redaction; counting-allocator tests; complexity tests on 64 KiB adversarial headers; four fuzz targets, each run for one hour clean.
- **CI.** A bare-metal `thumbv7em-none-eabi` build proves the core needs neither `std` nor an allocator; a dependency check proves parse-net is the whole tree; the fuzz targets build on every push and run weekly.

## Verification

- Local gate on Windows and WSL Ubuntu, Rust stable and 1.85: format, clippy in three feature modes, tests in three modes, examples, documentation with default and all features, and `cargo package` in a fresh target directory.
- Fuzzing: `cookie_header`, `cookie_lines`, `locate`, `set_cookie_build`, one hour each, no findings.
- CI green on every platform before the tag.
