# cookie-net v0.5.0 - Feature Complete

**Date:** 2026-10-23
**Compare:** [`v0.4.0...v0.5.0`](https://github.com/jamesgober/cookie-net/compare/v0.4.0...v0.5.0)

**The client side, and every planned item in place.** v0.5.0 added what an outbound HTTP client needs: a `Set-Cookie` parser and cookie-date algorithm that follow the rfc6265bis user-agent steps, and a bounded cookie jar that applies the storage and retrieval rules, fails closed on domain cookies without a public suffix list, and keeps its state behind a trait. With `Clear-Site-Data` support for cookie-bomb recovery, every P0, P1, and P2 item of the API now exists.

## What's in 0.5.0

- **`parse_set_cookie`** (feature `client`). The section 5.6 algorithm step by step: a control byte ignores the line, a missing `=` makes a nameless cookie, attributes are matched case-insensitively, a later attribute replaces an earlier one, attribute values over 1024 bytes are ignored, `Max-Age` follows its exact grammar and is capped at 400 days. Borrowed, no allocation.
- **`cookie_date`**. The section 5.1.1 tokenizer, with the two-digit-year rule and the 1601 lower bound.
- **`Jar`** (feature `jar`). `store` applies the section 5.7 steps a non-browser client needs: `Secure` only from secure origins, "leave secure cookies alone", the `__Host-` and `__Secure-` prefixes, nameless cookies that would plant a prefixed name, `SameSite=None` and `Partitioned` without `Secure`, replacement that keeps the creation time, the 400-day cap. `cookie_header` applies section 5.8.3: host-only and domain matching, path matching, `Secure`, `SameSite` against a `RequestContext`, partitions, longer paths first.
- **Fail closed without a suffix list.** With the default `NoSuffixList`, a `Domain` other than the request host is refused, so no site can set a cookie for `com` or `github.io`. Supply a `PublicSuffix` to share cookies across sibling subdomains.
- **Bounded, and portable.** `JarLimits` (50 per domain and 3000 in all by default) with expired-first, then least-recently-used eviction. State lives behind `JarStore` with `MemoryStore` as the default; `export` and `import` move a jar between processes or nodes in a checksummed format that `import` validates as untrusted input.
- **`CLEAR_SITE_DATA_COOKIES`.** The `Clear-Site-Data: "cookies"` value for a request whose credential lookup reports a truncated or over-long `Cookie` header.
- **`docs/ARCHITECTURE.md`**, and the jar export format in `docs/FORMATS.md`.

## Verification

- Local gate on Windows and WSL Ubuntu, Rust stable and 1.85, in every feature mode, and `cargo package` in a fresh target directory.
- A property test that every cookie the builder accepts reads back through the client parser with the same attributes, and that every header the jar writes reads back through the server parser; user-agent behaviour cases; a bounded-memory stream of 20,000 cookies; tampered exports refused.
- Fuzzing: `parse_set_cookie`, `cookie_date`, `jar_ops`, one hour each, no findings.
- CI green on every platform before the tag.
